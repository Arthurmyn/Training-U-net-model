# Эксперимент с равным размером обучающих данных (429 + 429, 5 сидов)

Что изменилось по сравнению с первым экспериментом (`runs/`, `results/`, они остаются как есть):

| | Первый эксперимент | Этот эксперимент |
|---|---|---|
| Обучающих изображений | Kvasir 800, CVC 429 | **429 и 429** (Kvasir: фиксированная случайная подвыборка, seed 42) |
| Сидов | 3 | **5** |
| Ранняя остановка | patience 15 | patience 15, но **не раньше 50-й эпохи** (`min_epochs: 50`) для обоих датасетов |
| Папки | `runs/`, `results/` | `runs_equal/`, `results_equal/` |
| Val и test | | **без изменений** (Kvasir 100/100, CVC 92/91) |

Почему `min_epochs`: в первом эксперименте обучение CVC-моделей останавливалось на 29-46 эпохе, пока Dice на train ещё рос (ошибка E10). Решение принято по кривым обучения, а не по тестовым результатам. Чтобы вернуть исходное правило, поставьте `min_epochs: 0` в `configs/equal_size.yaml`.
Это изменение протокола: опишите его в тексте работы и приведите результаты обоих экспериментов.

Аугментация осталась прежней и **не увеличивает число изображений**: отражения, поворот до 15 градусов и масштаб 0.9-1.1 применяются «на лету» (каждую эпоху новый случайный вариант). Копий данных на диск не сохраняется.

## Порядок действий на ноутбуке, где идёт обучение
```bash
git pull
python -m train.check_gpu                                           # обязательно: должно быть `GPU OK` (см. docs/SETUP_ru.md, раздел GPU)
python -m train.verify_data                                     # DATA OK
python -m pytest -q                                             # необязательно, ~1 мин
python -m train.run_all --config configs/equal_size.yaml --smoke   # проверка и оценка времени; затем удалите runs_smoke/
python -m train.run_all --config configs/equal_size.yaml --device cuda   # 10 запусков (можно прерывать и продолжать); --device cuda запрещает откат на процессор
python -m train.collect --config configs/equal_size.yaml           # собирает всё в final_results/
```
- Прикидка времени (по первому эксперименту на RTX 3050): около 10 с на эпоху; один запуск 8-17 минут, всего примерно 1.5-3 часа. Точную оценку даст `--smoke`.
- `collect` считает метрики заново по сохранённым весам; в этом конфиге на видеокарте (`extended.device: auto`), поэтому быстро. Запускайте его на том же ноутбуке, где лежат `runs_equal/*/best.pt`. Веса в git не попадают. Мелкие различия в числах с плавающей точкой между GPU и CPU допустимы: проверка A в `collect` сравнивает пересчёт с исходной оценкой.
- Если нужно проверить только обучение: `python -m train.run_all --config configs/equal_size.yaml --sources cvc --seeds 1`.

## Что появится
`final_results/` (маленькая папка, без весов): `README.md` с главными числами, `figures/`, `tables/`, `per_image/`, `runs/` (логи и результаты каждого запуска), `config/`, `audit/`, `MANIFEST.json` (контрольные суммы всех файлов, версии, коммит git).
Скопируйте её обратно (zip или `git add final_results runs_equal results_equal` + `git commit` + `git push`; файлы `*.pt` git игнорирует).

## Как читать результат
1. Если CVC-модели теперь обучились (в `figures/figA1_training_curves.png` train и val Dice вышли на плато, лучшая эпоха не в самом начале), метка `preliminary (E10)` больше не нужна: она задаётся ключом `extended.preliminary_sources` (в этом конфиге пусто). Если же они снова недообучены, верните `preliminary_sources: [cvc]` и пересоберите (`python -m train.collect ... --skip-inference`).
2. `figures/fig09_equal_size_comparison.png` отвечает на вопрос «объясняется ли разрыв разным числом обучающих изображений»: Kvasir-800 (первый эксперимент) против Kvasir-429 и CVC-429.
3. Равное число кадров не равно равному объёму информации: 429 кадров CVC это около 19 видеопоследовательностей, а 429 снимков Kvasir независимы. Это ограничение надо указать.
