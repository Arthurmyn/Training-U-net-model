# Полный запуск эксперимента

Если обучение идёт на арендованном сервере RunPod, используйте `docs/RUNPOD_ru.md` вместо SETUP и этого файла (там весь путь целиком).

Предполагается, что `docs/SETUP_ru.md` выполнен и все проверки прошли (`verify_data`, `pytest`, `--smoke`).

## Что будет сделано
Для каждого набора `sources x seeds` (по умолчанию Kvasir-SEG и CVC-ClinicDB, сиды 1-3, то есть **6 запусков**):
1. обучение U-Net на train-части; лучшая эпоха выбирается **по val**, test-часть при обучении не используется;
2. оценка: Dice на каждом изображении на (a) val и test **своего** датасета, (b) **всём другом** датасете (внешний тест).

Для проверки: Kvasir-SEG 800/100/100 и CVC-ClinicDB 429/92/91 (разбиение по видеопоследовательностям), списки в `outputs/splits/`.

## Запуск
```bash
python -m train.run_all --dry-run     # только показать план
python -m train.run_all               # весь эксперимент
```
- **Можно остановить (Ctrl+C) и запустить снова ту же команду**: завершённые запуски пропускаются, прерванный продолжается с последней эпохи.
- **Не давайте ноутбуку засыпать.** macOS: `caffeinate -i python -m train.run_all`. Windows: Параметры -> Питание -> «Никогда» для сна при питании от сети; подключите зарядку.
- Ноутбук будет греться: ставьте на жёсткую поверхность, не закрывайте. Для пробы на части данных: `python -m train.run_all --sources kvasir --seeds 1`.
- Фоновый запуск (macOS/Linux): `mkdir -p runs && nohup python -m train.run_all > runs/run_all.log 2>&1 &`, затем `tail -f runs/run_all.log`.
- Время: оценка из `--smoke`. На MacBook (MPS) я измерил примерно 24 с на эпоху для Kvasir и 14 с для CVC при 256x256 и базовой ширине 32; до 100 эпох, но ранняя остановка (15 эпох без улучшения) обычно заканчивает раньше.

## Что появится
```
runs/kvasir_seed1/
    run.json            настройки, версии, коммит git, лучшая эпоха, причина остановки
    metrics.csv         по эпохам: loss, Dice на train и val, lr, секунды
    per_image_dice.csv  Dice каждого изображения во всех оценках (главный результат)

```

## Перенести результаты обратно на основной ноутбук
Нужны только маленькие файлы (веса `*.pt` не нужны для статистики).

**macOS / Linux**
```bash
zip -r runs_results.zip runs -x "*.pt"
```
**Windows (PowerShell)**
```powershell
Get-ChildItem runs -Recurse -File | Where-Object { $_.Extension -ne ".pt" } | Compress-Archive -DestinationPath runs_results.zip
```
Распакуйте архив в корень проекта на основном ноутбуке (получится `runs/...`). Затем:
```bash
python -m train.analyze
```
Появятся `results/summary.md`, `results/fig_dice_distributions.png` и таблицы в `results/tables/`.
(Веса сохраните отдельно, если они нужны для воспроизведения или показа.)

## Что решить до запуска (значения по умолчанию мои, сверьте с методологией)
- **Гиперпараметры:** batch 16, AdamW lr 1e-3, до 100 эпох, остановка после 15 эпох без улучшения val-Dice, потеря BCE + Dice, порог 0.5 (`train_config.yaml`).
- **Аугментации (только train):** отражения (p=0.5), поворот до 15 градусов и масштаб 0.9-1.1 (p=0.5). В методологии указано «геометрические», конкретный набор выбран мной.
- **Число сидов** (3) и ширина сети (32 канала): ограничены временем; больше сидов даёт более надёжные оценки.
- **Метрика считается на масках 256x256**, а не на исходном разрешении.
- **Правила чтения доверительных интервалов** (пороги 0.05, 0.03, 0.10) заложены как «весь интервал выше / ниже порога, иначе неопределённо». Сверьте с гипотезами из методологии и при необходимости поменяйте в `train/analyze.py`.

## Чего эксперимент не покажет
Падение Dice на другом датасете измеряет **совокупный** эффект (яркость, разрешение, эндоскоп, стиль разметки, пациенты, число обучающих
снимков). Причину по отдельному фактору он не устанавливает. Разбиение CVC сделано по видеопоследовательностям, а не по пациентам:
перекрытие пациентов между train и test исключить нельзя (см. `outputs/audit_report.md`).
