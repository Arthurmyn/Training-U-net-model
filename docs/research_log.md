### 2026-10-18: код обучения
- Пакет `train/`: U-Net (BatchNorm, 7.76 млн параметров, 32 базовых канала), потеря BCE + soft Dice, AdamW lr 1e-3, batch 16, до 100 эпох, остановка после 15 эпох без улучшения val-Dice, лучшая эпоха по **val**, аугментации только на train (отражения p=0.5, поворот до 15 градусов и масштаб 0.9-1.1 p=0.5), порог предсказания 0.5, 3 сида.
  **Все эти значения выбраны мной как значения по умолчанию, не взяты из методологии RMT**; требуют сверки.
- Метрика: Dice на изображение (оба пусты = 1) на масках 256x256.
- Статистика (`train/analyze.py`): bootstrap 10000, 95%, для CVC пересэмплируются целые последовательности; пороги практической значимости 0.05 (основной), 0.03 и 0.10. Правила чтения интервалов выбраны мной.
- Проверка кода: 41 тест; быстрый тест на реальных данных; проверка, что модель способна переобучиться на 16 снимках (потеря 1.48 -> 0.68, train-Dice 0.28 -> 0.65 за 40 эпох).
- Окружение проверено на macOS (Apple Silicon), Python 3.9.6, PyTorch 2.8.0. Аудит воспроизводится с другой версией numpy (1.26 и 2.0): разбиения и графики идентичны.

### 2026-10-20: обучение и результаты
- Обучение выполнено на втором ноутбуке: **Windows 11, NVIDIA RTX 3050 6 ГБ (Laptop), Python 3.14.3, PyTorch 2.14.1+cu126, numpy 2.4.3** (отличается от протестированного окружения; в `run.json` записано `git_dirty: true`: на ноутбуке были правки кодировки UTF-8, затем закоммичены в d3f715d).
- Время: Kvasir около 19 с на эпоху (25-28 минут на запуск), CVC около 10-11 с на эпоху (5-8 минут на запуск).
- Результаты (среднее Dice, среднее по сидам): Kvasir -> Kvasir 0.822; Kvasir -> CVC 0.655; CVC -> CVC 0.378; CVC -> Kvasir 0.397.
- Падение Dice при переносе Kvasir -> CVC: 0.167, 95% ДИ [0.087, 0.252]; для CVC-модели падение -0.019, ДИ [-0.237, 0.182] (неинформативно).
- **Диагностика CVC:** train-Dice на лучшей эпохе 0.62-0.74 (у Kvasir 0.89-0.91), обучение остановилось на 29-46 эпохе (у Kvasir 79-89); val CVC состоит из 5 последовательностей и очень шумный; 33% тестовых кадров CVC-модель не нашла (Dice < 0.05).
  Вывод: CVC-модель недообучена, результаты по ней отражают это, а не только перенос между доменами.

### 2026-10-24: решения для эксперимента с равным размером данных
- Причина: у Kvasir 800 обучающих изображений, у CVC 429; в первом эксперименте CVC-модели недообучены (E10). Решения пользователя: Kvasir обучать на **случайной фиксированной подвыборке из 429 изображений** (одной для всех сидов), **5 сидов** (протокол: 2 x 5 = 10 запусков), условия обучения для обоих датасетов одинаковые, по окончании всё собрать в отдельную папку.
- Аугментацию в виде заранее сохранённых копий (400 + 400 + 400) решено не вводить: аугментация остаётся «на лету» (число изображений за эпоху не растёт, каждую эпоху новый случайный вариант); яркость не аугментируется, чтобы не смешивать её с возможной причиной переноса.
- Реализовано: наследование конфигов (`configs/equal_size.yaml`), фиксированная подвыборка (`outputs/splits/kvasir_train_subset_429_seed42.json`, команда `python -m train.subset`), `training.min_epochs: 50` для обоих датасетов (изменение протокола, основано на кривых обучения первого эксперимента), набор графиков для статьи (`train/paper_figures.py`), сборщик `python -m train.collect` (папка `final_results/`, MANIFEST с контрольными суммами). Первый эксперимент (`runs/`, `results/`) не изменён.
- Обучение этого эксперимента ещё не выполнено.
